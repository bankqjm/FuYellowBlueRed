# 一、项目概述（优化增强）

## 1.1 项目简介

FuYellowBlueRed 是**开源轻量化外卖配送 SaaS 平台**，覆盖本地餐饮下单、商家接单、骑手配送、平台管理、自动化分账、资金流水管理全链路，适配校园、社区小型外卖场景。

## 1.2 系统角色（明确权限边界）

- **普通用户（消费者）**：下单、支付、购物车、评价、退款、个人中心
- **商家管理员**：店铺管理、商品管理、订单处理、收入查看、提现结算
- **配送骑手**：接单、配送、订单确认、收入统计、余额提现
- **超级管理员（平台）**：用户 / 商家 / 骑手审核、数据总览、账务配置、安全管控

## 1.3 技术架构

### 前端
- 核心框架：React 18 + TypeScript
- UI 组件库：Ant Design 5
- 工程化：Vite、ESLint 规范、移动端自适应

### 后端
- 框架：FastAPI（高性能异步接口）
- ORM：SQLAlchemy
- 数据库：SQLite（单机开源版，可无缝迁移 MySQL）
- 认证体系：JWT 令牌认证

# 二、全局通用业务规则（原文档缺失，新增补充）

## 2.1 订单通用状态流转

待支付 → 待接单 → 待取餐 → 配送中 → 已完成
异常状态：**已取消（用户取消 / 超时取消）、已退款、已拒绝**

## 2.2 通用超时规则

1. 订单支付超时：**15 分钟未支付自动取消订单**
2. 所有超时订单：无资金变动、订单状态归档、可在订单列表查看

## 2.3 图片上传通用规范

- 允许格式：jpg、png、gif、webp
- 禁止格式：php、py、exe、svg、html、shell 脚本等可执行文件
- 用途：用户头像、评价图片、商家商品图、店铺封面

## 2.4 权限通用规则

1. 普通用户：仅可操作自身订单、钱包、资料
2. 商家：仅可管理**自己店铺**的商品与订单，不可操作其他店铺数据
3. 骑手：仅可查看**自己承接**的配送订单与收入
4. 平台管理员：拥有全局查看、审核、配置权限

# 四、账务体系（全面优化：补全规则、落地逻辑、统一口径 + 实现状态标注）

## 4.1 标准化资金流向（固定不可改）

&gt; 基于平台可配置比例自动分账

用户实付总金额 = 商品金额 + 配送费

1. 商品金额分账
- 商家实收 = 商品金额 × (1 - 商家抽成比例)
- 平台佣金 = 商品金额 × 商家抽成比例

2. 配送费分账
- 骑手实收 = 配送费 × (1 - 平台服务费比例)
- 平台服务费 = 配送费 × 平台服务费比例

### 示例（默认参数）

用户支付 ¥100
- 商品 ¥85
  - 商家实收：76.5 元
  - 平台抽成：8.5 元
- 配送费 ¥15
  - 骑手实收：12 元
  - 平台服务费：3 元

## 5.4 30 项安全漏洞**逐条整改结论**

### 严重漏洞 5 项（全部完成整改）

- 支付充值无限额 → 已加单笔 / 单日限额 ✅

### 高危漏洞 8 项（待 P1 迭代修复）

密码弱口令、登录无限流、管理员越权、潜在 SQL 注入、敏感日志、宽松跨域、错误信息泄露、无账户锁定

### 中危漏洞 12 项（P1/P2 分批加固）

前端 Token 风险、无 HTTPS、缺少安全头、上传大小绕过、订单枚举、无审计日志、会话不安全、商家越权操作、无限流、密码重置漏洞、依赖风险

### 低危漏洞 6 项（文档 &amp; 部署规范优化）

补齐安全文档、渗透测试规范、日志留存策略、数据备份策略、容器部署安全配置

## 5.5 风险矩阵优化结论

- 恶意充值、重复扣款：**极高风险（已闭环）**
- 恶意文件上传、Token 伪造、暴力破解：**高风险（待闭环）**
- 数据泄露、越权访问：**中风险（迭代加固）**

### PEP 8 规范要点
- 类名使用 CamelCase
- 函数/变量使用 snake_case
- 模块级常量使用 UPPER_CASE
- 行长度限制 120 字符
- 导入顺序: 标准库 &gt; 第三方库 &gt; 本地模块

### 阿里巴巴前端规范要点
- 禁止使用 `var`，使用 `const` / `let`
- 使用单引号
- 尾部逗号 (multiline)
- 箭头函数使用括号包裹参数
- `if` 语句必须使用大括号
- 使用 `===` 而非 `==`
- 使用 camelCase 命名变量/函数
- 对象属性周围使用空格
- 行长度限制 120 字符
